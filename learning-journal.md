## 2026-04-21 - React: первый компонент

### Что сделал
- Запустил Vite dev server и увидел HMR: страница обновляется сразу после сохранения `App.jsx`.
- Изменил стартовый экран Vite на учебную страницу "Мой React-дневник".
- Разобрал базовую связку `useState`, `count`, `setCount` и `onClick`.
- Сделал кнопку прогресса: при клике состояние меняется, а интерфейс обновляется.
- Добавил массив `topics` и вывел его на страницу через `map`.
- Исправил первую JSX-ошибку: лишний символ `>` в `map((topic) => ...)` и лишний вложенный `<li>`.
- Добавил условный текст через `count === 0 ? ... : ...`.
- Вынес список тем в отдельный компонент `TopicList`.
- Сделал коммит `Learn: create first React component`.
- Проверил production-сборку командой `npm.cmd run build`.

### Что понял
- JSX похож на HTML, но внутри него можно вставлять JavaScript через `{}`.
- `useState(0)` создает значение состояния и функцию для его изменения.
- Интерфейс в React обновляется от данных: меняется `count`, меняется текст на странице.
- `map` позволяет превратить массив данных в список JSX-элементов.
- Компоненты лучше называть с большой буквы, например `TopicList`.
- Props позволяют передавать данные из одного компонента в другой: `<TopicList topics={topics} />`.

### Ошибки / сложности
- В JSX легко ошибиться в скобках или символах, но сообщение Vite помогает найти место.
- В списке через `map` не нужен дополнительный внешний `<li>`, иначе получается неправильная структура.
- Build в sandbox-окружении упал с `spawn EPERM`, но вне sandbox команда `npm.cmd run build` прошла успешно.

### 3 вывода дня
1. React-компонент - это функция, которая возвращает JSX.
2. Состояние нужно менять через функцию вида `setCount`, а не напрямую.
3. Данные можно хранить отдельно, а интерфейс строить из них через `map`.
